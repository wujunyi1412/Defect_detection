# 暗缺陷细化与对比度计算：从零开始理解

本文解释项目中的两个新增函数：

```cpp
bool RefineDarkDefectGeometryAdaptive(
    const cv::Mat& gray_yolo,
    DetectionResult& detail);

float CalculateContrastRatioAdaptive(
    const cv::Mat& gray_img,
    const cv::Mat& binary_mask,
    int x, int y, int w, int h,
    ContrastPolarity polarity);
```

第一个函数负责把 YOLO 框收紧，并重新计算缺陷像素面积。第二个函数负责计算缺陷前景与周围背景的灰度比值。

本文按没有传统图像处理基础来讲。先理解概念，再讲代码步骤，最后讲项目中的调用顺序和排查方法。

---

## 1. 先认识几个基本概念

### 1.1 灰度图

灰度图中的每个像素通常是 `0～255` 的数字：

- `0` 表示黑色。
- `255` 表示白色。
- 中间数字表示不同程度的灰色。

例如正常背景灰度为 `200`，黑污灰度为 `100`，说明黑污比背景暗很多。

### 1.2 检测框（bounding box）

一个框用下面四个数字表示：

```text
x：左上角横坐标
y：左上角纵坐标
w：框的宽度
h：框的高度
```

YOLO 的任务首先是“找到大概位置”，所以 YOLO 框通常会比真实缺陷大。比如真实黑点可能只有 `5×4` 像素，YOLO 给出的框可能是 `20×19`。

### 1.3 二值 mask

mask 用来表示哪些像素属于缺陷：

```text
0   ：不属于缺陷
255 ：属于缺陷
```

可以把 mask 想成一张透明胶片。胶片上白色的位置覆盖缺陷，黑色的位置不参与前景统计。

### 1.4 前景和背景

- **前景**：当前要测量的缺陷像素。
- **背景**：缺陷周围正常材料的像素。

这里的“背景”不是整张图片的黑色外框，而是缺陷所在产品表面的正常区域。

### 1.5 面积

本项目中的细化面积是缺陷 mask 中非零像素的数量，不是外接矩形的面积。

例如下面的缺陷占 6 个像素：

```text
0 1 1 0
1 1 1 0
0 1 0 0
```

它的像素面积是 `6`，外接框是 `3×3`，外接框面积是 `9`。代码输出的 `detail.area` 应为 `6`。

### 1.6 对比度比值

新函数希望计算：

```text
contrast = 缺陷前景代表灰度 / 周围背景代表灰度
```

暗缺陷示例：

```text
前景灰度 = 100
背景灰度 = 200
contrast = 100 / 200 = 0.50
```

亮缺陷示例：

```text
前景灰度 = 210
背景灰度 = 150
contrast = 210 / 150 = 1.40
```

因此：

- 暗缺陷通常 `< 1`，越接近 `0` 表示越黑。
- 正常或与背景接近的区域通常接近 `1`。
- 亮缺陷通常 `> 1`，数值越大表示越亮。

## 2. 两个算法在完整流程中的位置

当前 YOLO 后处理顺序可以简化为：

```text
输入图像
   |
   v
转换为 8 位灰度图 gray_yolo
   |
   v
YOLO 输出类别、置信度、框、mask
   |
   v
CalculateContrastRatioAdaptive()
计算前景/背景灰度比
   |
   v
根据 contrast 判断 Stain / DarkClusters
   |
   v
use_traditional_measure == 1 ?
   |
   +-- 是 --> RefineDarkDefectGeometryAdaptive()
   |           更新 x、y、w、h、area
   |           用最终连通域 mask 重新计算 contrast
   |           按新 contrast 重新判断 Stain / DarkClusters
   |
   +-- 否 --> 保留 YOLO 几何和初次 contrast
   |
   v
按最终类别对应的 enable、confidence_threshold、contrast_threshold、
min_width、min_height、min_area 过滤
   |
   v
输出并画框
```

一个非常重要的细节：**对比度最多会计算两次。**

第一次在 YOLO 后处理阶段使用 YOLO mask，目的是获得初始对比度和初始 `Stain/DarkClusters` 类别。若传统几何细化成功，第二次直接使用细化函数内部的最终连通域 mask 重新计算。因此：

- 未启用细化或细化失败：`contrast` 来自 YOLO mask。
- 细化成功：`x/y/w/h/area/contrast` 都来自同一个最终连通域。
- 细化成功后会按新 `contrast` 重新判断 `Stain/DarkClusters`。
- 对比度阈值和尺寸阈值都检查最终结果。

## 3. 小黑点框和面积是怎样细化的

实现文件：`dark_defect_refiner_adaptive.cpp`

### 3.1 为什么只处理不超过 30×30 的框

函数入口有下面的限制：

```cpp
if (detection.width > 30 || detection.height > 30) {
    return false;
}
```

含义是：宽和高必须同时不超过 `30`。

这不是判断面积是否小于 `900`。例如 `100×5` 的面积只有 `500`，但它很可能是产品边缘长条，所以仍然不处理。

增加该限制的原因是：大块 stain 可能包含多个分离暗点或复杂纹理。只选择最强连通域时，大框容易突然缩成一个小点。当前策略是：

- 小框：使用传统算法精确收紧。
- 大框：返回 `false`，保留原 YOLO 框和原面积。

### 3.2 第一步：校正 YOLO 框

YOLO 坐标可能是小数，也可能靠近图像边缘。函数会：

1. 用 `floor` 计算左上角。
2. 用 `ceil` 计算右下角。
3. 把坐标限制在图像范围内。
4. 检查宽高是否有效。

这一步叫作 `clamp`。它用于防止 OpenCV 裁图时越界。

### 3.3 第二步：扩展 context

不能只观察 YOLO 框内部，因为框内可能大部分都是缺陷或错误分割，无法找到正常背景。

函数会在 YOLO 框四周增加一圈区域：

```text
+-------------------------+
|       扩展 context      |
|    +---------------+    |
|    |   YOLO 原框   |    |
|    |      ●        |    |
|    +---------------+    |
|                         |
+-------------------------+
```

扩展距离约为短边的 `30%`，并限制在 `4～24` 像素。

### 3.4 第三步：识别产品外部黑边

产品四周可能有黑色背景。若把它当成 stain，会得到一条细长黑框。

函数使用以下方法识别黑边：

1. 计算 context 灰度的第 `80` 百分位，估计正常亮材料的灰度。
2. 取该灰度约 `30%` 作为黑色候选阈值。
3. 找出低于阈值的黑色连通域。
4. 只保留与 context 四条外边相连的黑色区域。
5. 向产品内部膨胀 `1～3` 像素，覆盖黑到亮的过渡带。

“与外边相连”很重要：

- 产品外部黑背景通常会连到 context 边缘，因此被排除。
- 框内孤立的小黑点不连接 context 边缘，因此仍然是缺陷候选。

### 3.5 第四步：估计正常背景

函数优先使用 YOLO 框外、context 内的有效像素作为背景。

如果缺陷靠近图像边缘，框外有效背景太少，就退回使用框内四周的一条窄边带。

已识别的产品黑边不会参与背景估计。

### 3.6 第五步：拟合背景平面

真实图像经常存在照明渐变。例如左边灰度 `180`，右边灰度 `210`。此时不能用一个固定数字代表整块背景。

代码使用一个平面表示背景：

```text
background(x, y) = a*x + b*y + c
```

- `a` 表示水平方向亮度变化。
- `b` 表示垂直方向亮度变化。
- `c` 表示基础亮度。

这样每个位置都有自己的预测背景灰度。

### 3.7 第六步：估计背景噪声

即使没有缺陷，正常表面也不是完全相同的灰度。算法用背景拟合残差的中位绝对偏差（MAD）估计噪声：

```text
sigma ≈ 1.4826 × MAD
```

不需要记住 `1.4826` 的数学来源。只要理解：

- 正常纹理变化越大，`sigma` 越大。
- 阈值会自动变严格，避免把纹理当缺陷。
- 表面越平滑，`sigma` 越小，可以检测低对比度黑点。

使用中位数而不是普通平均值，是为了减少极黑、极亮异常像素的影响。

### 3.8 第七步：计算暗响应

暗响应可以理解为“当前像素比正常背景暗多少”。

算法计算两种响应：

```text
全局暗响应 = 拟合背景 - 当前像素
局部暗响应 = 高斯平滑背景 - 当前像素
最终响应   = max(全局暗响应, 局部暗响应, 0)
```

两种响应各有用途：

- 全局响应适合较均匀的暗污区域。
- 局部响应适合只有几个像素的小黑点。
- 取最大值可以兼顾两者。

### 3.9 第八步：强种子与弱生长

算法使用两个阈值，这种方法叫“滞后阈值”或 hysteresis：

```text
seed_threshold：严格阈值，寻找一定是缺陷的核心像素
grow_threshold：稍宽松阈值，补充缺陷边缘像素
```

当前小框使用：

```text
seed_threshold = max(2.0, 2.5 × sigma)
grow_threshold = max(1.5, 0.65 × seed_threshold, 1.75 × sigma)
```

直观理解：

1. 先找到非常可靠的黑点核心。
2. 再允许核心附近稍弱的暗像素加入。
3. 没有强核心的普通纹理不能独立成为最终缺陷。

### 3.10 为什么小框不用闭运算

闭运算可以连接断裂区域、填充小洞，但也可能把 `3×4` 的黑点扩大，或将旁边纹理粘到黑点上。

小框的目标是精确测量几个像素，因此当前小框不做 `3×3` 闭运算。

### 3.11 为什么使用四邻域连通

四邻域只认为上下左右相邻的像素属于同一区域：

```text
  上
左●右
  下
```

八邻域还会把四个斜角算作相邻。表面纹理经常通过斜角与黑点接触，导致框变大。

因此小黑点使用四邻域，可以减少斜向纹理粘连。

### 3.12 第九步：选择最佳连通域

一个 YOLO 框内可能出现多个暗区域。算法为每个连通域评分，主要考虑：

- 平均暗响应：越黑越可信。
- 强种子占比：可靠核心越多越可信。
- 填充率：区域越紧凑越可信。
- 面积：完全忽略面积容易选中单个噪点。
- 到 YOLO 框中心的距离：只作为较弱的辅助条件。

没有强种子重叠的连通域会被直接排除。

### 3.13 第十步：更新框和面积

选出最佳连通域后：

```text
x/y/w/h = 连通域的最小外接矩形
area    = 连通域实际像素数
contrast = 连通域前景灰度 / 局部预测背景灰度
```

最终连通域 mask 会直接传给 `CalculateContrastRatioAdaptive`。只有新对比度计算成功时才覆盖旧值；若背景不足导致计算失败，则保留 YOLO 阶段的旧对比度。细化结果不额外增加 padding，所以小点框会尽量贴近真实像素。

### 3.14 返回值是什么意思

```text
true  ：细化成功，detail 已更新
false ：没有可靠细化结果，detail 保持原值
```

返回 `false` 的常见情况：

- 输入图为空。
- 框无效或越界后为空。
- 宽或高超过 `30`。
- 没有足够背景。
- 没有超过强种子阈值的暗像素。
- 没有可靠连通域。

函数返回 `false` 不等于删除检测结果。当前调用端没有根据返回值删除结果，所以会保留原 YOLO 框。

## 4. 前景/背景对比度是怎样计算的

实现文件：`image_utils_adaptive.cpp`

### 4.1 输入 mask 可以是什么尺寸

新函数支持三种情况：

1. mask 与整张图一样大：裁出检测框对应位置。
2. mask 与检测框一样大：直接使用。
3. mask 是其他尺寸：用最近邻插值缩放到检测框大小。

最近邻插值不会产生大量中间灰度，更适合二值 mask。

### 4.2 为什么背景环必须能走到框外

旧思路先裁 YOLO 框，再在框内寻找背景。如果 YOLO mask 填满框，框内就没有正常背景。

新函数先根据 mask 面积确定背景距离，再扩展检测框：

```text
        背景环
    +-------------+
    |   +-----+   |
    |   |缺陷 |   |
    |   +-----+   |
    +-------------+
```

背景环与缺陷之间会留出一小段空隙，防止模糊边缘或缺陷晕染污染背景。

### 4.3 背景环大小为什么按 mask 面积变化

先将缺陷面积换算成等效圆半径：

```text
equivalent_radius = sqrt(area / π)
```

然后根据这个半径设置内外背景距离，并限制最大最小值。

含义是：

- `1px` 小点只使用附近的小背景环。
- 较大缺陷使用更宽的背景环。
- 不直接按 YOLO 大框决定背景距离，避免“大框包小点”时取到太远背景。

### 4.4 如何避免把产品黑边当背景

背景环生成后还会执行一次外部黑区检测：

1. 计算 context 的第 `10` 和第 `80` 百分位灰度。
2. 找到显著低灰度区域。
3. 只保留与 context 外边连通的暗区。
4. 膨胀 `1～3px` 覆盖边缘过渡。
5. 从背景环中删除这些像素。

例如一个 `1px` 黑点靠近产品黑边：

```text
黑边灰度       = 0
正常产品背景   = 200
缺陷前景       = 100
```

黑边不会成为分母，最终仍应得到：

```text
contrast = 100 / 200 = 0.50
```

### 4.5 为什么也要拟合背景平面

假设背景从左到右逐渐变亮：

```text
左侧背景 160  ->  中间 180  ->  右侧背景 200
```

若统一用 `180` 作分母，左边和右边相同程度的缺陷会得到不同结果。

新函数使用：

```text
predicted_background(x, y) = a*x + b*y + c
```

在每个缺陷像素的位置预测它本来应该有多亮。

### 4.6 什么叫稳健平面拟合

第一次用所有背景环样本拟合平面后，算法计算每个样本与平面的差值。

与平面差异过大的点可能是：

- 另一个缺陷。
- 噪声点。
- 残留黑边。
- 高亮反光。

算法使用 MAD 找出正常残差范围，只用正常样本再次拟合。这个过程比普通平均更不容易被异常点带偏。

### 4.7 每个前景像素单独计算比值

对 mask 中每个前景像素执行：

```text
ratio(x, y) = gray(x, y) / predicted_background(x, y)
```

例如：

```text
像素 A：前景 100，预测背景 200，ratio=0.50
像素 B：前景 105，预测背景 210，ratio=0.50
```

虽然两个位置原始灰度不同，但相对于各自背景的缺陷程度相同。

### 4.8 为什么不直接平均所有前景比值

YOLO mask 可能比真实缺陷稍大，包含一些接近正常背景的像素。直接平均会把暗缺陷的比值拉向 `1`。

暗缺陷采用较低的一段比值进行稳健平均：

```text
第 10 百分位 ～ 第 40 百分位
```

亮缺陷采用较高的一段：

```text
第 60 百分位 ～ 第 90 百分位
```

最极端的少量像素也不直接使用，可以降低单个坏点的影响。

当 mask 少于 `5` 个像素时，样本太少，不适合做百分位区间统计，因此使用中位比值。这就是 `1px`、`2×2` 小缺陷的处理方式。

### 4.9 Auto、Dark、Bright 的区别

```cpp
ContrastPolarity::Dark
```

明确按暗缺陷统计，适合 `Stain` 和 `DarkClusters`。

```cpp
ContrastPolarity::Bright
```

明确按亮缺陷统计，适合 `BrightStripes`。

```cpp
ContrastPolarity::Auto
```

先查看全部比值的中位数：

- 中位数 `<=1`，按暗缺陷处理。
- 中位数 `>1`，按亮缺陷处理。

### 4.10 计算失败和真实 0 怎样区分

现在 `0` 是合法对比度，表示前景相对于有效背景确实接近纯黑。
计算失败会返回 `NaN`。常见失败原因：

- 图像或 mask 为空。
- mask 没有前景像素。
- 检测框无效。
- 黑边排除后背景样本少于要求。
- 背景平面拟合失败。
- 预测背景接近零，除法不安全。

只有计算成功时才会用 contrast 重分类。合法的 `contrast=0` 会归为 `DarkClusters`；
`contrast=NaN` 不参与 `Stain/DarkClusters` 重分类。

## 5. 两个函数如何配合

假设 YOLO 输出：

```text
框：20×19
mask 面积：120
类别：Stain
```

实际图中只有一个 `5×4` 的黑点。

### 对比度阶段

`CalculateContrastRatioAdaptive` 使用 YOLO mask：

1. 在 mask 周围找有效背景环。
2. 排除产品黑边。
3. 拟合局部背景。
4. 得到例如 `contrast=0.62`。

### 几何细化阶段

`RefineDarkDefectGeometryAdaptive` 使用灰度图重新找小黑点：

```text
原框：20×19
新框：5×4
新面积：16
```

找到最终连通域后，函数使用这个精确 mask 再计算一次对比度。例如初始 YOLO mask 偏大时得到 `0.78`，细化后的真实黑点可能得到 `0.62`。最终保留 `0.62`，并用它重新判断 `Stain/DarkClusters`。

最终输出可能是：

```text
x/y/w/h：传统算法细化结果
area：传统算法细化像素数
contrast：传统算法最终连通域的局部前景/背景比值
score：YOLO 置信度
```

## 6. 当前项目中的启用位置

### 6.1 YOLO 对比度

`yolo_postprocess.cpp` 当前使用：

```cpp
CalculateContrastRatioAdaptive(...)
```

它会影响：

- 输出的 `detail.contrast`。
- `Stain` 是否按阈值变为 `DarkClusters`。
- 后续 `contrast_threshold` 过滤。

### 6.2 PatchCore 主结果对比度

`patchcore_postprocess.cpp` 当前也使用新函数计算 PatchCore 主结果的对比度。

### 6.3 暗缺陷几何细化

`result_builder.cpp` 在满足以下条件时调用新细化函数：

```text
类别是 Stain 或 DarkClusters
并且 use_traditional_measure=1
```

配置示例：

```ini
[Stain_config]
Enable=True
use_traditional_measure=1
confidence_threshold=0.25
contrast_threshold=0
min_width=1
min_height=1
min_area=1
```

### 6.4 为什么小框细化后可能不显示

细化后会再次检查：

```text
min_width
min_height
min_area
```

例如真实黑点细化为：

```text
w=3, h=4, area=9
```

若配置为：

```ini
min_width=5
min_height=5
```

该结果会被过滤，看起来像“细化后框消失”。如果要保留微小黑点，应将这些阈值设为 `1`，或按业务最小缺陷尺寸设置。

## 7. 用真实案例理解设计

### 7.1 小框包住小黑点

原始框：

```text
20×19
```

真实缺陷：

```text
5×4
```

旧的宽松生长和闭运算可能把纹理一起加入。当前小框策略使用严格阈值、不做闭运算、使用四邻域，目标是得到接近 `5×4` 的框。

### 7.2 大框变成一个小点

原始框：

```text
266×92
```

框内可能有多个纹理和暗点。如果只选最佳连通域，可能突然变为 `4×6`。

当前解决方法不是继续猜测，而是宽或高超过 `30` 时不细化，保留 YOLO 结果。

### 7.3 框靠近产品黑边

若背景环同时包含灰度 `0` 的产品外部黑区和灰度 `200` 的正常表面，直接平均背景会完全错误。

两个新函数都会识别与局部 context 外边连通的黑区，并排除黑到亮的过渡带。

### 7.4 横跨产品边缘的长框

例如 `448×26` 的框横跨产品上沿。它不是适合传统小点细化的目标。

现在因为宽度超过 `30`，函数直接返回 `false`，不会把边缘细化成 `249×3` 的伪缺陷条。

## 8. 常见问题排查

### 问题 1：大框没有变化

先检查宽高。任意一边超过 `30` 都不会细化，这是当前有意设置的安全限制。

### 问题 2：小框仍比黑点大

可能原因：

- 暗点本身存在竖向或横向拖尾。
- 暗点与附近纹理通过上下左右连接。
- 背景纹理噪声很强，生长阈值仍包含了一部分纹理。

建议保存无绘制框的原始灰度图，同时记录原框和细化框坐标后分析。

### 问题 3：细化后框消失

检查 `min_width`、`min_height`、`min_area`。算法不会把成功结果设为空，但后续过滤器可能删除过小结果。

### 问题 4：对比度接近 1

可能原因：

- 缺陷与背景确实很接近。
- YOLO mask 包含了太多正常背景。
- mask 与框坐标不匹配。
- 缺陷极小，而输入图经过缩放或插值后被平滑。

### 问题 5：对比度返回 NaN

依次检查：

1. 灰度图是否为空。
2. mask 是否为空。
3. mask 是否至少有一个非零像素。
4. 框是否在图像范围内。
5. 缺陷附近是否还有足够的正常产品背景。

### 问题 6：靠边缺陷的对比度异常

观察缺陷周围是否只有黑色外部区域而没有正常产品表面。如果有效背景样本不足，任何“前景/正常背景”比值都无法可靠计算，此时返回 `NaN` 比制造一个错误比值更安全。

### 问题 7：更换新函数后阈值是否还能直接使用

新旧函数的含义都是前景灰度除以背景灰度，但采样和稳健统计方法不同，数值可能发生变化。

特别是：

```ini
dark_clusters_threshold=0.8
contrast_threshold=...
```

建议使用一批已标注样本统计新函数的数值分布后再确定阈值，不要只凭一两张图设置。

## 9. 建议怎样验证算法

准备至少以下样本：

```text
1. 高对比度 1px 黑点
2. 低对比度 2×2 黑点
3. 5×8 的竖向暗点
4. 正常纹理但没有缺陷
5. 缺陷靠近上、下、左、右黑边
6. 背景存在亮度渐变
7. 大于 30×30 的片状 stain
8. 横跨产品边缘的长框
```

每张图记录：

```text
原始 YOLO 框
YOLO mask 面积
细化后的框
细化后的面积
contrast
最终类别
是否被 min_width/min_height/min_area 过滤
```

这样才能区分问题来自：

- YOLO 检测。
- YOLO mask。
- 对比度计算。
- 几何细化。
- 配置过滤。
- 最终画框。

## 10. 一页速查

```text
RefineDarkDefectGeometryAdaptive
  输入：灰度图 + DetectionResult
  处理：只处理宽高均 <= 30 的暗缺陷框
  输出：更新后的 x/y/w/h/area
  true：细化成功
  false：保持原结果

CalculateContrastRatioAdaptive
  输入：灰度图 + mask + 框 + 明暗极性
  处理：局部背景环 -> 排除黑边 -> 稳健平面 -> 前景/背景逐像素比值
  输出：暗缺陷通常 <1，亮缺陷通常 >1
  0：无法可靠计算

二者关系
  初次 contrast：来自 YOLO/PatchCore mask
  小框细化成功：geometry、area、contrast 来自同一个最终连通域
  小框细化失败：保留 YOLO geometry、area、contrast
  filter：最后仍会应用配置中的最小宽高和面积
```
